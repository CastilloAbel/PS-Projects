GAP #3: WORKSPACE AUTO-ADD ON BOARD MEMBERSHIP
Location: Backend/src/authMiddleware.ts, Lines 71-75
Severity: CRITICAL

CURRENT STATE:
- Adding user to board requires workspace membership first
- If user added to board but not workspace → Cannot access board
- Board membership alone is insufficient

PROBLEM CODE (authMiddleware.ts:71-75):
  const workspaceMember = await prisma.workspaceMember.findUnique({
    where: { userId_workspaceId: { userId, workspaceId: board.workspaceId } }
  });
  
  if (!workspaceMember) {
    res.status(403).json({ error: 'No tienes acceso a este board' });
    return;  // ❌ Blocks board access even with board membership
  }

IMPACT:
- Manual two-step process required (add to workspace, then board)
- Users added to board can't see it
- Confusing permission flow

RECOMMENDATION (Choose one):
OPTION A (RECOMMENDED):
  if (!workspaceMember && boardMember) {
    // Auto-add board members to workspace
    await prisma.workspaceMember.create({
      data: {
        userId,
        workspaceId: board.workspaceId,
        role: WorkspaceRole.MEMBER
      }
    });
  }

OPTION B:
  // Allow board access without workspace membership
  // (for external collaborators)
  if (!workspaceMember && !boardMember) {
    return 403;  // No access
  }

ESTIMATED EFFORT: 1-2 hours
